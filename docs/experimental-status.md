# Experimental source snapshot

Dr. Doom is an independent community project built on Gentle Shell/Pi. It is not an official Gentle distribution, security certification or endorsement. A public repository may use the Gentle Hub topic `gentle-hub-project`; discovery is eventual and does not certify the project.

## Included boundary

- Local Qwen3-8B Q4_K_M, CPU4/GPU0, context32768/output2048 and one concurrent request.
- The full disposable Gentle4.6.0/Pi1.5.0 harness with pinned native4.3.1 and explicit image selection.
- Local CTF/pentest/red-team methodology prompts, not a complete scanner platform, network-target authorization system or independent vulnerability validator.
- Optional legacy host profiles and widget source with their narrower boundaries.
- Dormant provider protocol foundations; this snapshot does not include the incomplete external-provider launcher, subscription entitlement or paid-provider acceptance.

No eco mode, model weights, retrieved runtime/build, credentials, private assessment work, operational logs or private development history are included.

## Evidence, not promises

One synthetic full-harness CPU model → real `read` → authoritative final response scenario passed independent evidence review. The cold run took **45min57s**, with normal shutdown/cleanup. No-prompt native/RPC/TUI component checks are narrower evidence. These observations do not validate every tool, complete assessment workflows, vulnerability efficacy, interactive latency, thermal behavior or other machines.

The source snapshot's offline checks passed **32 named tests** using the mock loader and serial execution. Those mocks do not execute real model inference or authenticate to vendors. Installation, image builds, native-image integration and model checks remain separately opted-in operations.

Review authority is candidate- and scope-specific. Documentation, old evidence, an independent audit or a directory listing never grants native approval, remote authorization or delivery rights. Do not infer whole-source approval from a documentation-only review slice.

## Image selection and resources

Keep an existing canonical image unchanged. On the original validation machine the measured image may be selected explicitly using the full ID in [installation](install.md#observed-local-candidate-2026-11-06). Elsewhere build and validate your own candidate, then pass its immutable full ID via `DOOM_LOCAL_IMAGE_ID`.

No new image or thermal benchmark is implied by publishing source. CPU4 inference and builds can create sustained load and heat; this release provides no thermal-control guarantee. Local requests retain their finite3600s limit, which is not a test budget or retry grant. Prefer bounded, serial, resource-limited development checks; do not silently activate GPU/cloud or shrink the harness/context to claim equivalent results.

Own code is MIT; model, runtime, package, catalog and widget rights remain separate. See [third-party boundaries](third-party.md) and [installation](install.md) before retrieval or redistribution.
